# 「宝塚の実力」第3回以降の公開手順（承認記録方式）

運営者に端末操作（PowerShell・秘密鍵・署名コマンド）を求めない方式。第2回は従来の署名方式のまま公開を続け、第3回以降にだけ使う。

## 毎週の流れ（毎週土曜日に公開。時刻は固定しない）
1. 原稿を作り、独立監査（一次資料の全数照合）とPM確認を終える。原稿は `status: "draft"`、`plannedAt` は公開予定の土曜日。
2. 運営者が、チャットなどで「公開してよい」と**明示**する。これが公開承認。
3. Claude Code が承認の根拠を書き残す：`node scripts/series-tool.js record-approval <slug> --by <承認者名> --evidence "<いつ・どこで承認されたか>"`（status は draft のまま）。
4. 公開日（土曜日）に：`node scripts/series-tool.js publish <slug>`（承認記録が有効なときだけ `published` と `publishedAt` を書く）。
5. `npm test`、`check --strict`、`check --deploy`、`npm run build` が通ることを確かめ、その回のJSONだけを commit・通常 push。
6. CI と Cloudflare Pages を確認し、`node scripts/series-tool.js verify <slug>` で本番の内容ハッシュが承認した原稿と一致することを確かめる。

## 防ぐこと
- **無承認の公開**：承認記録（承認者・承認日時・根拠・内容ハッシュ）が無い／欠けている `published` は、ビルドを止める。`draft` と `scheduled` は出さない。
- **承認後の編集**：承認記録は原稿の内容ハッシュに結びつく。承認後に本文を変えると公開されない（再承認が必要）。`status`・`publishedAt`・`plannedAt` は制御項目でハッシュに入らない。
- **日付の誤り**：公開日は土曜日だけ。未来の日付はその日になるまで出ない（日付だけを見る。時刻は見ない）。承認日時が未来の記録は止める。
- **公開済みの回が消える変更**：第N回が公開されるのに、第2〜N-1回が公開されない状態は `check`（CI・Cloudflareのビルド前検査）が失敗にする。
- **第2回の降格**：v3の記録は第3回以降だけ。第2回を署名なしの記録に差し替えても、ビルドが止まる。

## 限界（重要）
承認記録は**署名ではない**。リポジトリに書き込める人は、偽の承認記録を作れる。この方式が防ぐのは、うっかりの公開・承認後の編集・承認の書き忘れであり、悪意ある書き込みではない。
承認の根拠（`evidence`）に、運営者の承認がいつ・どこにあったかを必ず書き、あとから確認できるようにする。より強くしたい場合は、GitHub のブランチ保護（main への変更に運営者のレビュー承認を必須にする）を併用する。

## 従来の署名方式（第2回の検証用）
`approve`・`finalize`・`keygen` は残してあるが、新しい回では使わない。第2回の公開を保つため、ビルドは公開鍵（`SERIES_APPROVER_PUBLIC_KEY`）で第2回の署名を引き続き検証する。この変数は消さない。
